## Headline

Yesterday's three open triggers all resolved inside 24 hours, and one new minor landed on top:

1. **The effect 4.0.5 npm skew is resolved — NEVR-156's gate is GREEN.** Core `effect@4.0.5` published 10-15 **01:27 UTC** (registry `time`), 24 minutes after its satellites (01:03). `latest` = 4.0.5, core resolves, satellites' `^4.0.5` peer ranges are installable. The "guard" row from yesterday can retire: the bump gate (verify core resolves on npm) passed; NEVR-156 can proceed to 4.0.5 directly, skipping 4.0.2→4.0.4 staging.
2. **effect@3.22.3 shipped this morning** (10-16 00:37 UTC) — a v3-line backport of three real fixes: LayerMap preload entries now follow idle TTL instead of pinning for the map's lifetime (#8513, preload skipped when TTL is 0 — the default), `Reloadable.auto` hanging on scope close (#8612), and interrupted acquisition no longer fails an uninterrupted scope closure in `addFinalizer`/`acquireRelease` (#8271). Dev pins `effect 3.22.0`; this is a safe patch path for the v3 tree while the strangler migration runs. Satellites moved in lockstep (`@effect/sql-pg` 0.53.1, `platform-bun` 0.91.3, `platform-node` 0.108.3, `rpc` 0.76.3, `cluster` 0.60.4).
3. **@tanstack/db 0.15.0 landed 30 minutes after yesterday's report** (10-15 03:45 UTC) — and NEVR-211's pin of 0.14.0 + 0.6.0 merged to `effect/v4` at `8343e07` two hours *before* 0.15.0 existed. 0.15.0 is a real minor with a **breaking window-semantics change**: `findOne` keeps its compiled limit of 1 (`setWindow({limit:3})` on a findOne now throws `SetWindowFindOneLimitError`; unordered findOne accepts only offset 0), and in exchange includes load **only for the rows a windowed query or findOne actually shows** — late pages cost the same as the first. No `findOne`/`setWindow` call sites exist in the Stellarc tree today (verified: 0 matches), so nothing breaks — but the sync engine and every paginated live feed should be written against 0.15.x, not 0.14.x, or the pin is stale the day the sync work starts. electric-db-collection 0.6.1 and tauri-db-sqlite-persistence 0.2.35 (claim-loss recovery intact) repointed to 0.15.0 the same morning.
4. **LiveStore shipped stable 0.5.0** (10-15 16:14 UTC) — the "dev-tag noise until stable 0.5" trigger from yesterday fired. The release aligns its **Effect 4 dependency cohort to 4.0.3** (AI, OTel, platform, SQLite, Vitest packages): LiveStore is now an Effect-4-native stable sync runtime. ADR 0007's Electric choice stands — the sync engine is in flight and LiveStore's model (its own event log, not a shape protocol) is a different architecture — but it moves from "noise" to the strongest named alternative if the Electric path stalls.
5. **@effect/vitest 4.0.5 is real but gated on Vitest 5**: peer range is `vitest >=5.0.0 <6.0.0`, while dev and `effect/v4` both pin **vitest 4.1.10** (verified in both manifests). Adopting Effect-native test contexts rides a Vitest 4→5 major (5.0.5 stable since 10-15). No pin today; calendar with the hono 5 / Vite-majors batch.
