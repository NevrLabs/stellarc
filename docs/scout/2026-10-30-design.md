## Headline

**DESIGN.md went from a pattern we track to the format the agent-UI world has standardized on — and the hub is bigger than shadcn.** [`VoltAgent/awesome-design-md`](https://github.com/VoltAgent/awesome-design-md) is **124,627★** (MIT; created 2026-03-31; pushed 10-28; star count verified through two independent API reads), holding **84 brand DESIGN.md files** (`design-md/` tree counted: linear.app, vercel, stripe, notion, claude, apple, airbnb…) plus a commercial site on top — [getdesign.md](https://getdesign.md): a 550+ entry website catalog, Website/Mobile App Starter Kits, a "Request a DESIGN.md" service, and a Video Studio. There are translation forks (JP at 997★, one at 464★) and derivative packs (SymonChu/design-md-templates, 74 files). The format itself — front matter (`version: alpha`, name, description) plus `colors` / `typography` token blocks plus prose reasoning — is exactly what our own lane already touches twice: the shadcn DESIGN.md workflow-skill trial (radar since 10-14) and onsystem's `export --format design-md` (which 0.11.0 just made *correct* — see below). What this changes for Stellarc: the post-freeze design-system merge should publish **our own DESIGN.md as a first-class artifact** — generated from `apps/stellarc-ui`, hand-tuned, read back clean by onsystem — beside the lint-in-CI, diff-at-PR, and MCP-at-edit channels. And the collection is directly minable: the `linear.app` file is a 24KB token-level extraction of the exact aesthetic Stellarc chases (near-black `#010102` canvas, four surface levels `#0f1011…#191a1b`, three hairline weights, lavender `#5e6ad2` as the *only* chromatic accent — "never decoratively"). That is this run's ADOPT proposal (proposal 1), with a ready-to-file brief.

**The dgesteves pair kept shipping — both again on 10-29 — and each release lands on a seam we own.** [`onsystem`](https://github.com/dgesteves/onsystem) went 0.10.3 → **0.11.1** and 73★ → **165★** (+92 in two days; pushed today). **0.11.0** makes the ESLint plugin editor-grade — a lint after a pause drops from 345–387 ms to 33–70 ms on a large app (dub's `apps/web`), a rule turned off in config stops being reported without an ESLint restart, two configs in one process no longer mix — and fixes the DESIGN.md export to write Tailwind's spacing scale *as steps* (`"1": 0.25rem` … `"96": 24rem`, so `p-[13px]` advises `p-12`, not `p-[4px]`), typography aliases as the level they name, and a DTCG export that no longer double-counts tokens (50 → 42 on a stock shadcn app). **0.11.1** widens zero-config to find a design system in a flat `src/components/`, `components/`, or `app/components/` of components wrapping a primitives library (React Aria, Radix, **Base UI**, Headless UI, Ark UI — our exact shape) with a 4-in-5 import guard, and stops counting `@radix-ui/react-icons` as a primitives library. Amendment to the pending NEVR-332 promotion brief: **pin `@v0.11.1`** (proposal 2). [`signoff-ui`](https://github.com/dgesteves/signoff-ui) went 0.12.0 → **0.13.0** and 31★ → 44★. **0.12.1** fixes what an approver *sees*: `ApprovalCard` now shows **every** argument that comes with a command — `{ command: 'rm -rf build', dangerouslyDisableSandbox: true }` previously rendered as just `$ rm -rf build` — a security-relevant disclosure rule for our #115 card; a repeated object in arguments/output no longer shows (and, worse, *sends*) the string `"[Circular]"` to the tool when approved from the JSON editor; `DiffReview` names comments on removed lines by the original file's lines. **0.13.0** gives AG-UI interrupts answer integrity: one answer per interrupt (a second answer — retry, second card, app button — previously started a *second* resumed run with the opposite decision), a resume that fails before starting takes the answers back and re-asks with the failure in `error`, and an interrupt past `expiresAt` accepts only a cancellation. ## Proposals

### 1. ADOPT — publish a Stellarc DESIGN.md as a first-class artifact of the post-freeze design-system merge

File: **Multica brief posted in this run's issue comment** (ready for Talos to file). Summary: generate `DESIGN.md` for `apps/stellarc-ui` via `onsystem export --format design-md` (0.11.1's export is now token-correct), hand-tune the reasoning sections, version it in-repo beside the lint config, and gate on onsystem reading it back clean (`inspect` reports no unresolved references). Mine the awesome-design-md `linear.app` / `vercel` / `stripe` files for dark-palette and type-scale reasoning patterns (the file is a reference, not a copy source — ours must describe *our* tokens). The DESIGN.md completes the four-channel enforcement stack the freeze taught us we need: lint-in-CI (`@shadcn/lint`), diff-at-PR (onsystem Action), MCP-at-edit (onsystem MCP), and **rules-in-context (DESIGN.md + the skill that points agents at it)**. No runtime dependency; blocked on the T02 decision by definition (it documents the design system the freeze protects); cost ≈ one maintained file.

### 2. ADOPT (amendment to the pending NEVR-332 promotion brief) — pin onsystem at `@v0.11.1`, and cite the two new objections it answers

No new issue: amend the 10-27 promotion brief when Talos files it. (a) The pin moves from `@v0.10.3` to **`@v0.11.1`** — seven releases in seven days; `@v0` floats a CI gate on someone else's morning. (c) 0.11.0's ESLint-plugin latency (33–70 ms warm) makes the in-editor channel practical for builder agents, not just CI — cite it in the MCP-install decision.

### 3. ADOPT (addendum to the 10-28 signoff-ui spec-delta brief) — fold 0.12.1/0.13.0 into the #115/#118 specs

No new issue: extend the brief filed 10-28 (it was Talos-to-file). For #115 (approval card): **every** argument a command carries is rendered — flags like `dangerouslyDisableSandbox` are exactly what an approver must see; repeated objects in arguments must never display or transmit a placeholder (`"[Circular]"`) — guard the JSON-editor approve path; comments on removed diff lines are named by the original file's line numbers. For the approval flow generally: one answer per interrupt (no double-resume), a failed-before-start resume re-asks with the error surfaced, and an expired interrupt accepts only a cancellation. Same posture as 10-28: steal the semantics, not the dependency.
