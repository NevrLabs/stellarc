## Headline

**signoff-ui shipped its protocol layer: 0.13.0 (this morning) fixes the exact failure class our open PR #110 exists for.** [`signoff-ui`](https://github.com/dgesteves/signoff-ui) (43★, +12 in a day; MIT; npm 0.12.0 → **0.13.0** with 0.12.1 between, both 10-29) is the shadcn-registry kit for agent diff-review and tool approvals that return a result the agent receives. **0.13.0's changelog is AG-UI robustness: answer each interrupt exactly once; take back answers a resume never sent; respect `expiresAt`.** Under AG-UI's interrupt model, a human answer is an event on a wire — a resume that never delivered it must retract the UI's "answered" state, a duplicate interrupt must not be answerable twice, and an approval offer past its expiry must stop being accept able at all. That is precisely the surface of our **#110 (NEVR-229: interrupt-safe transcripts + self-kill refusal guard)**, and the `expiresAt` half adds a contract question nothing in our tree answers yet: an approval request needs a TTL the backend stamps and the UI honors, or a stale card can approve a run that no longer wants it. 0.12.1 is distribution hygiene — per-item versioned registry dependencies (each item asked for at its published range, typechecked in a fresh app), undefined arguments omitted beside a command, a Tailwind-v3 mono-font escape — the boring fixes that say the kit is being installed in real apps. We still build, not install (lane frozen; #115 owns the card) — but the interrupt semantics are a spec delta for #110 that costs nothing to record now. That is this run's ADOPT proposal (proposal 1), with a ready-to-file brief.

**onsystem 0.11.x turned the design-system guard into a two-sided tool — and our own trial PR executed the pin-style proposal before the promotion did.** [`onsystem`](https://github.com/dgesteves/onsystem) (73★, MIT; npm 0.10.3 → **0.11.1**, two releases 10-29) is the diff-scoped design-system guard whose NEVR-332 trial completed 10-27. **0.11.x is two things:** an **ESLint plugin with real editor manners** — lint answers arrive before the background design-system look, and config edits, rule-option changes, and suppression comments all correctly invalidate the cached answer (the failure mode that makes a lint plugin get uninstalled) — and a **token export round-trip**: spacing steps written in scale order, typography aliases preserved, merged tokens keep their category, DESIGN.md ↔ tokens round-trips with no DTCG duplicates, plus a CLI reference with a drift test and measured performance. The round-trip matters beyond the tool: our radar already carries "shadcn DESIGN.md workflow skill" (TRIAL) — onsystem now generates and validates that file mechanically, which is the missing half of the skill. Meanwhile in our own repo, **#134/#135 were re-pushed 10-28 19:06–19:15 (NEVR-333 rework): the Action is now pinned to the v0.10.0 release-commit SHA `5d4edfd`, with a comment-proof, job-anchored wiring test** — yesterday's "pin it, don't float `@v0`" proposal is already executed on the trial pair, in the strongest form (SHA, not tag). One amendment for the pending promotion brief: the pin should move **deliberately** to a v0.11.x SHA when promoted, so the ESLint plugin and token round-trip land with it (proposal 2).

**The design-studio tier arrived: dotUI composes a design system and exports it as shadcn registry items — the exact shape of our post-freeze theme work.** [`mehdibha/dotUI`](https://github.com/mehdibha/dotUI) (1,369★, MIT, beta; pushed 10-28) — new to the radar — is "the design system studio for humans and agents": compose colors, typography, icons, density, radius and **per-component styles** on live, accessible components built on **React Aria + Tailwind**, preview every change, then export via `npx shadcn add @dotui/button` or straight into v0 (Bolt and Lovable "on the way") — plain files land in your repo, no package to depend on. It is tweakcn's category done one level deeper (tweakcn edits a theme; dotUI composes a system and owns the export pipeline). For Stellarc the value is the pipeline, not the runtime: our converged `base-nova` theme could be composed and maintained in a studio, then exported through the same registry channel the post-freeze design-system merge already needs (@shadcn/registry + shadscan are on the radar for that). Caveats: beta ("expect APIs to change before 1.0"), and React Aria under the hood ≠ our Base UI choice — we'd use the studio for tokens/composition and keep our component base. Second pattern row: [`elevenlabs/ui`](https://github.com/elevenlabs/ui) (2,439★, MIT) is a company shipping its agent kit as a **first-party shadcn registry** (`r/all.json`, own CLI beside it) — the distribution precedent for a future `@stellarc/design-system` registry. And affectui (378★, +16) sharpened its positioning to "UI for AI agents — agent trees, tool calls, traces, handoffs" with a component set that is now openly lane-adjacent (`tool-call-card`, `decision-inbox`, `change-summary`, `progress-tracker`, `thinking-loader`, each in clean + styled pairs) — elevated to a steal-reference for #115/#118 surfaces.

## Proposals

### 1. ADOPT (steal-into-spec) — fold signoff-ui 0.13.0 interrupt-answer semantics into #110 (NEVR-229) and #115

File: **Multica brief posted in this run's issue comment** (ready for Talos to file). Summary: record three rules on the interrupt-safe-transcript spec (#110 / NEVR-229) and the approval card (#115 / NEVR-239): (a) a human answer binds **exactly once** — a duplicate/interrupted offer is not answerable a second time; (b) a **resume that never delivered an answer must retract the UI's answered state** (the card returns to pending, and the transcript records the retraction, not a phantom approval); (c) approval offers carry an **`expiresAt`** the UI honors — past expiry the card shows expired and the accept path is dead client-side. (c) is the one contract change: the transcript DTO needs an approval TTL field the backend stamps — flagged for the api-contract owners (`docs/api-contract.md`), same open-question pattern as yesterday's `awaitingHuman` marker. No dependency, no UI work while the freeze holds; the deltas land with #110/#115 when the lane opens.
