## Headline

Three things moved since Friday. First, **`@effect/sql-drizzle` is dead for v4 — not delayed, removed**: the Effect monorepo's `packages/` on main is now `ai, atom, effect, opentelemetry, platform, sql, tools, vitest` (no sql-drizzle), npm still serves only 0.51.0 (2026-07-13, peers `effect ^3.22.0`), and no v4 tracking issue exists. "Wait upstream" from the 10-09 report is no longer an option — but Stellarc already answered it: **PR #77 (`agent/nevr-22`) vendors a drizzle⇄Effect v4 bridge at `packages/drizzle-effect`** (fiber-context-threaded, `SqlClient`-participating, `SqlError`-typed) and runs `effect 4.0.2` against it. The right move is to promote that bridge from migration workaround to owned dependency. Second, **Bun 1.4.3 ships `bun check`** — a built-in TypeScript checker that is a port of typescript-go, passes 100% of TypeScript 7.0.2's 51,210-test conformance suite, runs 3–6.4× faster than `tsc 7.0.2` with 2.2–4.9× less memory, and is verified by Bun against Effect's own source (913 mutations, zero missed errors). That retires the 10-09 "TS 7 spike" proposal in favor of something cheaper: tsgo-class speed with zero compiler-dependency change. Third, **Effect v4 quietly grew an `eventlog` module** — typed event sourcing (`EventLog`, `SqlEventJournal` over any `SqlClient`, encryption, remote replication, IndexedDB journal, reactivity hooks), marked unstable. Stellarc's axis event log is exactly this shape; upstream now maintains a version of it.

Also this run: **effect 4.0.4 landed today** (5 patch releases in 12 days — GA 4.0.0 on 10-01, then 10-05, 10-07, 10-11, 10-13), ACP stabilized **session compaction + session notices** (schema v1.25) and opened a **v2.0.0-alpha** line, and `@tanstack/db` hit 0.13.0 with a maturing persistence-collection ecosystem (`tauri-db-sqlite-persistence` exists — relevant to the desktop shell).

## Proposals

### 1. ADOPT — promote `packages/drizzle-effect` to an owned adapter; fold the sql-drizzle upstream death into the record
Upstream evidence this run: the v4 monorepo no longer contains sql-drizzle, npm has no 4.x line, and no tracking issue exists — the 10-09 "wait upstream" option is closed. PR #77 already carries a vendored bridge (`packages/drizzle-effect/src/index.ts`: drizzle `QueryPromise` → `Effect` failing with `SqlError`, execution through `effect/sql` `SqlClient` so transactions and tracing spans participate, per-fiber `Context` threading instead of a module-global). File the follow-up: give the bridge first-class tests (transaction participation, concurrent fibers, nested transactions, `SqlError` typing), a README noting it supersedes `@effect/sql-drizzle`, and a tracking note for `drizzle-orm` 1.0 (the bridge talks to `pg-proxy` directly, so the old `<0.50` cap is gone). Also bump the v4 branches from effect 4.0.2 → 4.0.4 before merge.
*(Issue brief posted as a separate comment for Talos.)*

### 2. ADOPT — Bun 1.4.3 + `bun check` as a fast typecheck gate
Bun 1.4.3's `bun check` passes 100% of TS 7.0.2's conformance suite (51,210 tests), is 3–6.4× faster and uses 2.2–4.9× less memory than `tsc 7.0.2`, and Bun mutation-tested it against Effect's own source (913 mutations, 0 missed). Concretely: bump `packageManager` bun 1.4.0 → 1.4.3, then add a CI step that runs `bun check --no-pretty` next to `tsc --noEmit --pretty false` and diffs outputs (the blog's own recipe). If the diff stays empty over a week of runs, bun check becomes the every-PR gate and tsc stays the authoritative release gate. This delivers the 10-09 "TS 7 spike" answer at a fraction of the cost — no compiler dependency changes.
*(Issue brief posted as a separate comment for Talos.)*

### 3. WATCH — two upstream developments to re-check next libraries run
(a) Effect v4's **`eventlog`** module (unstable): `SqlEventJournal` + encryption + replication + IndexedDB is axis's event log with upstream maintenance. Spike after the v4 migration: stand `SqlEventJournal.layer` on a scratch SQLite client and diff capabilities against the hand-rolled journal. (b) **ACP v2.0.0-alpha** + stabilized session compaction (v1.25): bump the SDK 1.7.0 → 1.8.0 in the routine batch, and before building any new ACP surface, check what v2 stabilizes — the subagents RFD in particular overlaps Stellarc's multi-agent session plans.
