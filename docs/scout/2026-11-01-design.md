## Proposals

### 1. ADOPT — brief (ready to file): agents-directory health layer, stolen from `r/registries.json`

**Title:** Agents directory: per-agent health layer (status, score, availability) modeled on shadcn's registry directory

**Description:** The agents-directory mockup (#78, branch `design/agents-directory`) and the BYO-runtime page (#75) list third-party agents and runtimes. Every listing will face the same question a shadcn user faces with a community registry: *is this thing reliable enough to install?* shadcn's answer — live since ~09-16, now covering 525 entries — is a per-entry health object we should copy almost verbatim:

- `status`: `observing` (probation for new listings) → `healthy` / `degraded` / `unavailable`; today's directory distribution is 421/19/43/42 out of 525 — degraded and unavailable entries stay listed, not deleted.
- `score` 0–100 with a four-way breakdown. Domain-mapped for Stellarc: **reliability** → run-success rate over the window; **correctness** → event-stream/contract compliance (does the agent emit the schema it declared); **installability** → onboarding success (does a first-time connect complete); **hygiene** → metadata completeness (display name, owner, capabilities, consent surface).
- `availability7d` / `availability30d` rolling windows; `statusReason{code, message}` machine-readable (e.g. `healthy_thresholds`); `firstObservedAt` / `checkedAt`; `hidden` flag for quiet delisting.
- Publish the object on the directory payload itself so the UI renders trust without a second fetch; re-check on a fixed cadence (shadcn's checks ran within the hour of this writing).

Scope it as a design+data-contract deliverable on the agents-directory work: one health DTO, one checker service skeleton, one rendering state set (probation badge, degraded banner, hidden). No new dependencies; the pattern is MIT-adjacent public JSON, not code. Talos decides filing.
