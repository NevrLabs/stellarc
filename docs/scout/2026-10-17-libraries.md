## Headline

npm was quiet on the effect line (4.0.5 / 3.22.3 stand), but three real movements landed — and one of them is inside our own CI:

1. **The T02 frozen-UI guard now fails every `effect/v4`-based PR unconditionally — including yesterday's db-0.15 brief (PR #112).** The guard (`tests/unit/desktop.test.ts:142`) diffs `apps/stellarc-ui` against `merge-base(origin/dev, HEAD)`. `effect/v4` itself carries **19 changed UI files** since forking from dev (verified: `git diff --name-only <fork-point> origin/effect/v4 -- apps/stellarc-ui` = 19 files), so any PR stacked on v4 inherits all 19 in the diff — PR #112's `foundation` log shows exactly `expected [ …(19) ] to deeply equal []` while touching zero UI files (its diff: `bun.lock`, ADR 0007, `package.json`, one integration test). Proof by contrast: PR #110 (base=dev, no UI files) passes `foundation`. Consequence: NEVR-156, NEVR-233, and every agent PR on v4 show a red check reviewers must not read as breakage — and the v4→dev merge PR itself will fail this guard unless the T02 decision lands first. This sharpens tomorrow's design-beat escalation (day 5): the freeze is no longer only a UI-scope question, it is a merge-gate mechanic for the whole v4 line. *(Brief below.)*
2. **@tanstack/db 0.15.1 is cut on main and imminent.** The Version Packages commit (`d10f41a`, 10-16 20:23 UTC) bumps the full 40-package cohort; `packages/db/CHANGELOG.md` on main shows three patches: orderBy index-fallback **explanation** (#2196), eager preloads settling after collection restart (#2173), and — the one that matters for us — **the first window of an ordered live query now publishes synchronously instead of possibly empty** (#2159/#2154 territory: "prevents an empty initial result when the first ordered request cannot fill the window"). Not yet on npm at run time (`latest` still 0.15.0; `0.15.1` absent from versions). NEVR-233/PR #112 pins 0.15.0/0.6.1; when 0.15.1 publishes, fold it into #112 before merge — a one-line pin bump for a fix in exactly the window semantics the sync engine's live feeds will rely on.
3. **ACP shipped twice yesterday**: schema **v1.26.0** + rust 1.12.0 + npm SDK **1.9.0** (10-16 10:03/11:30 UTC). 1.26.0 is unstable-channel only — client system-prompt schema added (#2361), next-edit-suggestions removed (#2266), forked-session-active clarified (#2359). ## Proposals

### 1. ADOPT — fix the T02 guard's merge-base so effect/v4-based PRs get honest CI *(brief below)*
The frozen-UI guard compares `apps/stellarc-ui` against `merge-base(origin/dev, HEAD)`, which for any v4-stacked PR is the v4 fork point — so the guard reports effect/v4's own 19 UI files on every such PR (PR #112 red with zero UI changes; PR #110 green on dev). One-line class of fix: pin the guard's baseline to the fork-point diff of the *base branch* (or run the frozen-tree assertion only when the base is dev), so v4 PRs are judged on their own delta. This is CI/process, not application code — and it decides whether the v4→dev merge PR can ever go green.

### 2. ADOPT (fold, no new brief) — take @tanstack/db 0.15.1 inside PR #112 when it publishes
0.15.1 is cut on main (changelog live, npm pending) with the ordered-live-query first-window fix (#2159) — the empty-initial-result case the sync engine's windowed feeds will hit on day one. When it appears on npm, bump #112's pins 0.15.0→0.15.1 / 0.6.1→(next electric patch) before merge. Patches only; no API movement; zero `findOne`/`setWindow` call sites exist yet.
