## Proposals

### Proposal 1 — ADOPT brief: desktop log-seam write safety (a dead output sink never kills the shell)

**Precedent (verified):** Multica #10566 (MUL-9213, +37/−0, merged 11-14 05:44Z) — when nothing
read the desktop app's stdout, **the first log line crashed the main process** with an uncaught
`write EPIPE` ("A JavaScript error occurred in the main process"); reproduced with a reader that
had already exited, "common for a GUI launch on Linux."

**Our seam (verified this run at dev `032d880` and effect/v4 `65fbe9a`):**
`desktop/src/lib.rs` emits its structured startup lines with `eprintln!` — effect/v4 `log_event`
(:27); dev has two sites: `log_event` (:56) **and the NEVR-632 `panic_hook` itself (:101)**. By std
contract, `eprintln!` **panics if the write fails** — so on dev, a broken stderr pipe turns any
logged event into a panic *inside the panic hook* (panic-in-panic → abort), and NEVR-632's
"record, never swallow" law is one dead pipe away from killing the recorder. The health-probe
thread (`probe_health` → `log_event`) writes after startup, when the launcher is most likely gone.

**Work:** checked writes at every seam site (`let _ = writeln!(io::stderr().lock(), …)` — a dead
sink drops the line, never panics), including inside the panic hook; a regression test that logs
against a closed stderr and asserts no panic; the Linux launch-smoke grep contract unchanged.
Sibling laws already in-tree: NSH #1865 / NEVR-632 (record, never swallow — this completes it:
*the recorder survives a dead sink*), Paseo #8810 (degrade to the daemon, don't die).
**Ready-to-file brief posted as an issue comment.**

### Proposal 2 — four pre-registrations (laws with no Stellarc surface yet, grep-verified at v4 `65fbe9a`)

1. **Never-delivered idempotent send** (Paseo #9580): an idempotency key's outcome must distinguish
   *never-reached-provider* from *delivered-outcome-unknown*; retrying a never-delivered send
   delivers it. No client-supplied messageId exists in Stellarc (idempotency is internal only —
   `store.ts:614`, push rows on seq/sha); lands when a client-retry/interrupting-send lane opens.
2. **Derived classification from live state** (Multica #10573→#10611): a view's grouping is
   computed at read time, never frozen into the creating event/notification. No board/inbox surface
   in apps/web yet; folds into the board-lane acceptance lines when filed.
3. **Self-hosted plain-HTTP** (OpenHands #19732): every SecureContext-only browser API
   (`crypto.randomUUID`, `crypto.subtle`, `navigator.clipboard`) has a fallback path. apps/web
   greps clean today — pin as an acceptance line / lint pass when the count grows.
4. **Copied-state isolation** (Paseo #9672): state copied for dev/test/seeding never carries
   restart recovery — a copied runtime may observe, never resume. No restart-recovery concept in
   Stellarc yet; folds into the runner-lifecycle brief at pickup.
