## Proposals

### 1. ADOPT — desktop packaged-app panic logging (ready-to-file brief)

NSH #1865 states the law: **a packaged app's panics are written to its log file** — the failure is observable, never swallowed by the GUI. Our shell has exactly the gap: `desktop/src/main.rs:2` sets `windows_subsystem = "windows"` for release builds, so a panic in the packaged Windows app prints nowhere (no console exists); nothing writes it to a file either — grep-verified 11-13: no panic hook, no log-file target in `desktop/` (`lib.rs` has only stdout `log_event`, which the Linux launch smoke greps). The seam already exists: `log_event()` at `desktop/src/lib.rs:26` and the never-log-tokens rule at `lib.rs:11`. Acceptance lines: (a) a panic hook installed at startup routes through the existing log seam into a persistent log file under the app's log dir (Tauri path API), in dev and packaged builds alike; (b) the hook respects the lib.rs no-tokens rule; (c) the Linux launch smoke asserts a synthetic panic lands in the file (it already greps log lines — `lib.rs:32`); (d) the panic still fails the process visibly (non-zero exit), never swallowed; (e) the log path is emitted once at startup so a user can find it. No new dependencies (std panic hook + Tauri path resolver). Brief posted in the run comment; Talos decides whether to file.

### 2. WATCH (pre-registration) — desktop lifecycle-honesty bundle (extends the 11-12 update-honesty row)

Three more NSH laws join the pre-registered desktop-distribution checklist, alongside #1865's panic-logging line which is split out as today's ADOPT brief: **launch at login** (#1884 — a distribution-parity marker, config not code, when the lane opens); **the app backgrounds while its screen cannot be seen** (#1867 — occlusion honesty: no busy work for hidden windows); **session-end state save** (#1744, in v0.5.0 — survive OS shutdown/logout with state intact); and **embedding apps may leave the runtime's optional parts out** (#1886 — also ADR 0015 review input: a client that embeds the runtime should only pay for what it uses). These become acceptance lines whenever desktop distribution/lifecycle is chartered.
