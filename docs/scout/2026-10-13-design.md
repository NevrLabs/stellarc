# Scout: design — 2026-10-13

Beat: **design** — templates and kits for trackers and agent UIs, shadcn/ui blocks, Radix/Base UI, icon sets, motion, dark-theme palettes, design-system references. First design-beat run, so every row is new to the radar, grounded in what Stellarc actually ships today.

Method: GitHub REST API (`gh api`), npm registry (+ download counts). Web search backend down a **fourth** consecutive run (`9router` unregistered); no claim below depends on it. Repo grounding verified directly: `apps/stellarc-ui` is a shadcn-dialect codebase — **62 `ui/` components, 43 files importing `@base-ui/react`, exactly 2 still importing Radix** (`form.tsx`, `timeline.tsx`, both `Slot` only) — matching ADR 0008's "Base UI via shadcn Base variants" decision.

## Headline

Three things matter for Stellarc this run.

**1. shadcn now ships agent-chat primitives in our dialect.** The registry grew `message`, `bubble`, `message-scroller`, `attachment`, `marker` components (added to new-york-v4 2026-06-29, #11051; registry-wide `cn` migration #11758 2026-09-04), built on a **new headless primitives package `@shadcn/react` (0.3.1, 2026-08-31)**. `MessageScroller` solves the exact hard part of an agent-transcript surface: streaming auto-scroll anchoring, scroll-position restoration, jump-to-latest — the stuff you must not hand-roll. And they ship in **base, radix, and now aria (React Aria) dialects** (64 aria component docs) — our Base UI choice is a mainstream lane of shadcn, not a side branch. Our agent chat today is a hand-rolled 200-line floating bubble (`ai/ai-chat-bubble.tsx`); the real transcript surface (the core of the product) should start from these.

**2. Our Radix→Base migration is 97% done and doesn't know it.** Only 2 `Slot` imports remain, but `package.json` still carries **19 Radix dependency entries (18 `@radix-ui/*` + the `radix-ui` umbrella)**, and — the real footgun — **`components.json` still says `style: "new-york"`**, the Radix dialect. The next `shadcn add <component>` in this repo fetches Radix-dialect source into a Base UI codebase, silently reintroducing the old primitives one component at a time. shadcn even shipped a first-party **`skills/migrate-radix-to-base`** skill (in-repo, with per-component class/prop mapping references) proving this is now a supported, paved path.

**3. Our motion/icon stack is quietly falling behind while usage is still small.** `motion` 14.2.0 published **today**; `framer-motion` (our pin, `^12.42.2`, 4 import sites) is now a rename-alias for `motion`, two majors behind (13 in Aug, 14 in Oct). `lucide-react` crossed **1.0 stable in March 2026**; we pin `^0.577.0` pre-1.0. `react-day-picker` 10 is out (May); we pin exact `9.14.0`. All cheap now, all more expensive as the UI grows.

## Proposals

### 1. ADOPT — build the agent-transcript surface on shadcn chat primitives
`ai/ai-chat-bubble.tsx` is a 200-line hand-rolled bubble with manual size-persistence; the product's core surface — streaming agent transcripts with tool calls, attachments, and system markers — needs more, and the transcript-viewer design PR (#73) is open right now. `shadcn add message bubble message-scroller attachment marker questionnaire typeset` (base dialect) plus `@shadcn/react` gives: `MessageScroller` (auto-scroll anchoring, position restore, jump-to-latest — the classic transcript bugs, solved), `Message`/`Bubble` rows (docs: "render reasoning steps, tool calls and assistant messages"), `Attachment` cards, `Marker` for system notes and session dividers, `Questionnaire` for structured agent questions, and `Typeset` (one owned CSS file, streaming-safe markdown styling) for reply prose. Do it as the foundation for the transcript UI, not a rewrite of the toy chat bubble: when the real session view lands, it starts from these parts and the chat.md rule ("never hand-roll scroll containers") becomes repo law.
*(Issue brief posted as a separate comment for Talos.)*

### 2. ADOPT — finish Radix→Base: drop 19 deps, fix `components.json` (dialect + `@coss`)
Two files still import Radix — `form.tsx:3` (`@radix-ui/react-slot`) and `timeline.tsx:3` (`radix-ui` umbrella) — both `Slot`-only. Swap them to Base-dialect equivalents (shadcn's `migrate-radix-to-base` skill has the mapping tables; a 10-line local Slot via `cloneElement` is the zero-dependency fallback for `timeline.tsx`, which has no shadcn base variant). Then remove all 19 radix entries from `package.json`, and fix `components.json` twice over: flip `style` from `"new-york"` (radix dialect) to the base style so the next `shadcn add` fetches Base variants, **and delete the `@coss` registry entry** — AGPL upstream (ADR 0008 already rules "inspiration only"), zero components installed, one accidental add away from contamination. Optionally adopt `cn` (one zero-dep package replacing `clsx` + `tailwind-merge`) to match the upstream registry. Smaller lockfile, faster installs, dialect and license footguns both removed.
*(Issue brief posted as a separate comment for Talos.)*

### 3. ADOPT — dependency-currency pass on the frozen UI: motion 14, lucide 1, react-day-picker 10
The freeze protects pixels, not versions. `framer-motion@^12.42.2` → `motion@^14` (rename import in 4 files; 13→14 changelog is API-stable for our usage: `motion.div`, `AnimatePresence`); `lucide-react@^0.577.0` → `^1.56` (1.0 stable since March, icon API unchanged); `react-day-picker@9.14.0` → `^10.0.2` (major; verify `calendar.tsx` props); while in there, relax the exact `mermaid@11.17.2` and `shiki@4.3.1` pins to carets. All verified against npm registry today. Cheapest now while usage counts are single-digit files.

## Notable non-findings

- Web search down a fourth consecutive run (`9router` unregistered). GitHub + npm carried the whole beat again — including download counts, which settled the assistant-ui-vs-primitives question (both healthy; size and shape were the issue, not health).
- **Park UI is gone** — `park-ui/park-ui` 404s on GitHub API. Any radar or doc still citing it is stale.
- shadcn templates bumped to **Next 16.4** and the repo added a community-registries directory (2026-10-12) — neither affects a Vite SPA.
- The new **aria (React Aria) dialect** with 64 documented components is strategically reassuring (Base is one of three paved lanes, not a bet) but changes nothing for us.
- Dark palette audit: our hand-written zinc (`#0a0a0b` bg, `#131315` card, alpha-based accents, deliberate `color-scheme` handling for third-party `light-dark()` components) is coherent and Linear-grade; no oklch migration warranted while frozen.
