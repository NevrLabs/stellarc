## Headline

**The dgesteves pair shipped three more times on 10-30 — and this drop is about making the *enforcement channel itself* trustworthy, which is exactly the objection class left in front of NEVR-332.** [`onsystem`](https://github.com/dgesteves/onsystem) went 0.11.1 → **0.12.1** (0.11.2 + 0.12.0 + 0.12.1, all 10-30; ten releases in ~2.5 weeks; 165★, pushed 10-30). **0.12.0** fixes the two ways a design-gate can lie in CI: an option that belongs to another command (`check . --out report.json`) now **exits 2 instead of being silently ignored** — a typo'd flag can no longer produce a false-green run — and a `check`/`inspect`/`export`/`init` run from a subfolder with no config of its own (`app/settings`) now resolves and reports the project above it (`Checking the project in ../..`) instead of finding zero config and declaring "No problems in 1 file." Both land directly on our shape: the Action would run against `apps/stellarc-ui` inside a monorepo. Plus `--max-warnings=-1` (ESLint parity) and `check --require-design-system` naming what each monorepo project lacks. **0.12.1** halves warm hook latency (470→311 ms on one file, 712→415 ms on dub's `apps/web`) via Node's compile cache + dep-derived design-system caching, and hardens the on-disk footprint: everything cached lives in a **user-only-writable folder**, others-writable folders are skipped with a warning, and a **SECURITY.md inventories every file written** — the same injection/safety posture 0.10.1 brought to MCP output, now applied to the filesystem. **0.11.2** fixes `--help` accuracy and adds MCP `search_components` synonyms (Sheet/Accordion/Textarea/Slider/Calendar/Command; Avatar by "profile"/"initials"). Amendment to the pending NEVR-332 promotion brief: **pin `@v0.12.1`** (proposal 1). [`signoff-ui`](https://github.com/dgesteves/signoff-ui) went 0.13.0 → **0.14.0** (10-30; 44★). **0.14.0 names task-list checkboxes** in rendered markdown ("Task", via the new `labels.markdown.task`): GFM `- [x] Read the route` renders a disabled unnamed checkbox, which **axe reports as a critical `label` violation** — and agents write these lists constantly as their plans, so this is a live a11y spec line for our transcript renderer, not a nicety. It also keeps an AG-UI thread answerable when a resumed run breaks off: a run that starts then dies (`RUN_ERROR`, broken stream, `stop()`) no longer strands the thread — interrupts reopen, a card whose tool never ran asks again, one whose tool ran is answered with `resolve`; and `toAcpMessage` reads a turn cancelled mid-write as **stopped, not done**. Breaking edge: `SignoffLabels` translations need the new `markdown.task` key. Addendum to the filed spec-delta brief for #115/#118 (proposal 2).

ESLint-plugin latency cites from the 10-30 amendment stand.

### 2. ADOPT (addendum to the 10-28 signoff-ui spec-delta brief) — fold 0.14.0 into the #115/#118 specs

No new issue: extend the filed brief. For #118 (transcript): **every GFM task-list checkbox our markdown renders gets an accessible name** ("Task") — unnamed disabled checkboxes are axe-critical `label` violations and agents emit `- [x]` plan lists constantly; budget the label as part of the markdown component, with a translation key from day one (upstream needed a breaking `SignoffLabels` change to add it late). For #115 (approvals/interrupts): define the mid-stream-death contract — a resumed run that errors before finishing **reopens its interrupt cards**: a tool that never ran asks again, a tool that ran resolves with its outcome; a turn cancelled while the agent was writing reads **stopped, not done** (it did not complete; done implies success).

### 3. ADOPT (amendment to the 10-30 DESIGN.md brief) — carry a CJK typography section conditional on CJK locales

No new issue: one paragraph added to the filed brief. The DESIGN.md format went locale-aware this week (JP fork at 998★ exists *specifically* to fix agents building Japanese UI from Latin-only specs; a Korean cited-brand catalog and a JP contracts repo followed). Ours should therefore include a **CJK typography section — line-height, punctuation handling, font stacks — marked as activating iff `i18n/` ships a CJK locale**, plus the JP fork's extension as the reference for what that section must cover. Everything else in the 10-30 brief (generate via `onsystem export --format design-md`, hand-tune, gate on clean read-back, mine `linear.app` for dark-palette reasoning) stands.
