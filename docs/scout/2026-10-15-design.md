## Proposals

### 1. ADOPT — build the agent-transcript surface on shadcn AI elements (`trace` + `code-block` + composite patterns)

When the UI freeze lifts (T02 decision with Talos), extend PR #91's chat-primitive foundation with the AI-elements set in the `base-nova` dialect: install `trace` and `code-block` from the registry, then compose `tool`, `subagent`, `test-results`, `confirmation`, and `chain-of-thought` following the documented patterns (they're recipes over the two primitives + badge/button — copy-in, ours to own). Map directly to Stellarc's run model: `tool` ↔ ACP tool calls (NEVR-129 bump pending), `subagent` ↔ delegated runs, `confirmation` ↔ the scoped permission pipeline just landed in NEVR-198, `test-results` ↔ CI rollups on agent PRs. Port rule from the findings: strip the docs-app `icon-placeholder` import, substitute lucide icons. This makes the Multica-grade agent-transcript UX a composition exercise instead of a from-scratch design problem, and it inherits shadcn's a11y/dark-theme defaults for free. No new runtime dependencies (registry items bring only `cn` + Base UI we already have).
*(Issue brief posted as a separate comment for Talos.)*

### 2. TRIAL — pre-register the transcript-data adapter as part of the AI-elements port

The AI elements are unopinionated about data — `TraceLine` takes `status: running|error|pending`, `Tool` renders input→output, none of it knows ACP/Effect shapes. Rather than letting run-view components grow ad-hoc prop drilling, pre-register (design-note, no code yet) a thin `RunEvent → element props` adapter layer at the port: one mapping file per element family (tool-call events → `Tool`, permission requests → `Confirmation`, sub-agent spawns → `Subagent`). This keeps the frozen-UI surface composition-only and makes the eventual live-transcript wiring (streaming, jump-to-latest already in PR #91) a data problem, not a layout problem. Revisit when T02 resolves.

### 3. WATCH — T02 decision aging; escalate gently on day 5
