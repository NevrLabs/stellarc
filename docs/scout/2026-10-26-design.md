## Headline

**The agent-design-governance lane is turning into a product category — and this run found the missing half of our T02 middle path.** Two purpose-built tools launched 10-06 from the same author, both MIT, both iterating fast. [`onsystem`](https://github.com/dgesteves/onsystem) (73★, pushed 10-25; npm `onsystem` **0.10.0, 2026-10-23** — ten releases in three weeks) "keeps coding agents on your design system": it catches raw palette colors, native elements your system replaces, and APIs your system lacks — **at every edit** via an MCP server (listed in the MCP registry; one-click install for Claude Code, Cursor, VS Code, Codex, Gemini, Copilot CLI) and **at pull request** via `dgesteves/onsystem@v0`, which checks only the lines a PR changed. That is two things `@shadcn/lint` (trial #127) is not: diff-scoped instead of whole-tree, and in-editor instead of CI-only. Layered — lint governs usage contracts in CI, onsystem catches palette/native-element drift where agents write code — they form the credible replacement for the whole-tree freeze: contracts on the *diff*, not the tree. Three weeks old and single-author, so: trial, not adopt. Trial brief filed this run (proposal 1).

**Second: the first shadcn-registry kit purpose-built for agent review/approval — and it badges ACP.** [`signoff-ui`](https://github.com/dgesteves/signoff-ui) (31★, pushed 10-25; npm **0.10.2, 2026-10-25**) ships React components for **multi-file diff review and tool approvals that return a result your agent receives** — the result channel is the part AI elements lack (they are display-only, which is why PR #115 pre-registers its own approval-card shapes). Distributed as a shadcn registry, badge-verified integrations: AI SDK 6/7, AI Elements, assistant-ui, **AG-UI, ACP**, Next.js/Vite; gzip per import 0.4–90.7 kB; keyboard-driven (Y approves). Too young to adopt over in-flight work, but it is the exact shape of our approval card (#115) and the diff-review surface we don't have yet. Steal its interaction pattern now, trial the kit when the design lane unfreezes (proposal 2).

**Third: the ecosystem references around us moved, our own queue did not.** [`hermes-workspace`](https://github.com/outsourc-e/hermes-workspace) (6,760★, MIT, v2.3.0, pushed 10-26) is the closest open-source implementation of the surface Stellarc is building — chat, terminal, memory, skills, inspector, plus a swarm control plane with role dispatch and byte-verified review gates. It's Hermes-only (we are agent-agnostic by design) but it is MIT pattern-mineable layout for our transcript/workspace/inspector panels. And `@shadcn/registry` **0.2.0 (10-16)** extracts the registry client out of the CLI into a programmatic package (fetch/resolve/install; 0.1.0→0.2.0 in two weeks, ships from `shadcn-ui/ui` `packages/registry`) — the install path for a post-freeze design-system merge, and the natural pair for shadcan drift audits. Meanwhile our six freeze-gated PRs (#90/#91/#92/#108/#115/#118) and the #127/#128 lint-trial pair all sit unchanged since 10-24 (check runs re-verified live this run), and `ui-design-contracts` still exists only on the trial branches, not on dev. The freeze decision remains Talos's; the tooling around it keeps getting better.

## Proposals

### 1. ADOPT (trial scope) — onsystem as the diff-scoped second layer of the design-contract stack

File: **Multica brief posted in this run's issue comment** (ready for Talos to file). Summary: run `dgesteves/onsystem@v0` as a **non-blocking** step on a follow-up to the #127 trial branch, so its catches (raw palette colors, native elements, missing design-system APIs — diff-scoped) sit beside `@shadcn/lint`'s usage contracts on the same diffs. Success criterion: onsystem runs clean on #127's diff and flags #128's seeded violations (or a deliberate raw-color seed if it doesn't) — then the T02 decision brief gains its third option with live evidence: freeze → lint contracts (CI) + onsystem (diff + MCP in-editor). No runtime dependency, no agent wiring in the trial; MCP install for our builder agents is a later, separate decision. Timebox two weeks; exit criteria recorded either way. We never add dependencies in scout runs — the brief is the deliverable.

### 2. WATCH (steal) — signoff-ui's result-channel approval + hermes-workspace's control-plane layout

Two reference mines, no adoption: (a) signoff-ui's approval card returns a structured result the agent receives — the exact semantics PR #115 is pre-registering; lift the interaction model (keyboard-first, result-enum shape) into #115's review, and slot a diff-review surface trial (the kit itself, post-freeze) into the transcript roadmap after #108/#115 land. (b) hermes-workspace's chat/terminal/memory/skills/inspector IA plus its swarm review-gate UX is the best MIT-licensed layout reference for our workspace/inspector panels — worth a deliberate look before we freeze our own navigation.

### 3. WATCH — @shadcn/registry (programmatic installs) + AG-UI handed to the libraries beat

`@shadcn/registry` 0.2.0 is the install mechanism for the post-freeze design-system merge (scriptable pulls + shadscan drift audits on top); no consumer until then, but it should be named in the design-system merge brief when that lands.
