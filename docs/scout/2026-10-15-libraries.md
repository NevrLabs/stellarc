## Headline

Three things this run, one operational trap:

1. **effect 4.0.5 shipped this morning** (GitHub release 2026-10-15 01:03 UTC; 33 packages) — but with a **publish skew on npm**: the satellite packages (`@effect/sql-pg`, `@effect/platform-bun`, `@effect/opentelemetry`, `@effect/atom-react`, … all at 4.0.5, peers `effect ^4.0.5`) are live on npm while **core `effect@4.0.5` returns 404 and is absent from the version list** (checked three times over 20 min; `latest` still 4.0.4). An explicit `bun add @effect/sql-pg@4.0.5` today resolves a peer that does not exist. The 4.0.2→4.0.5 bump riding NEVR-156 must gate on core actually resolving on npm, not on the GitHub release. Content-wise 4.0.5 is a pure patch, and several fixes land directly on in-flight Stellarc work (row 1).
2. **`effect/v4` is finished but unmerged** — PR #96 merged 10-14 (NEVR-49 done), branch pins `effect 4.0.2`, sits 10 ahead / 25 behind dev, and PR #99 (NEVR-185, yesterday's TRIAL brief — MCP port onto `effect/ai` McpServer, dropping `@modelcontextprotocol/sdk`) is open against it. Yesterday's proposal 1 is in flight; no re-brief.
3. **The v4 tree ships a reactivity system nobody radar'd**: core `effect@4.0.4` exports `./reactivity` (Atom, AtomRegistry, AtomRef, Hydration, AtomHttpApi, AtomRpc — source-marked `@stability unstable`) with first-party React/Solid/Vue bindings (`@effect/atom-react` et al., since 4.0.0 GA, `useAtom`/`useAtomSuspense`/`useAtomRefresh`/`useAtomSubscribe` hooks, peers `react ^19`). It is Effect's native answer to the react-query layer the UI leans on (682 `useQuery`/`useMutation` call sites). Unstable today → WATCH, not a migration call — but it changes what "Effect-native UI" can mean after the v4 merge.
