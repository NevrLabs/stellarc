## Headline

**signoff-ui turned real overnight: two substantive releases on 10-28 that map one-to-one onto PR #115 and PR #118 — an a11y pass on the approval card, then an attribution model that refuses to bill person-time to the agent.** [`signoff-ui`](https://github.com/dgesteves/signoff-ui) (31★, MIT, pushed 12:10 UTC today; npm **0.10.2 → 0.12.0 in three days**) is the shadcn-registry kit for agent diff-review and tool approvals that return a result the agent receives — the exact surface #115 hand-builds. **0.11.0** is an accessibility hardening of that card: after Approve-all/Deny-all, focus moves to the first card it answered (not the page body) with a spoken announcement; a focused card reads risk → what will run → the rule a lasting decision saves; releasing a critical press says "Confirmation cancelled"; commands/paths/JSON/diff lines stay LTR inside RTL pages (bidi isolation); forced-colors keep a border on primary buttons; touch text fields are 16px so iOS doesn't zoom, and key hints hide on touch. **0.12.0** adds `pendingClientTools` — the names already passed to `deriveAgentState` — and makes the timeline, status pill and meter **report the run, not the person**: a call a human answers shows no duration, no waterfall bar, and is never announced "finished in" that time; while waiting it reads "Needs approval" with no clock. A run ended with a sub-agent still running reads `stopped`, not `done`; a call a policy rule denied after a human approved reads "Blocked by policy," not "Denied by user"; the run meter's total never reads below its time to first token. Every one of those semantics belongs in our transcript: person-latency must not pollute agent-duration telemetry (#118), and the approval card's focus/RTL/forced-colors/touch behavior is #115's checklist. We still don't adopt the dependency (the lane is frozen and #115 already owns the shape) — we fold the semantics into the specs. That is this run's ADOPT proposal (proposal 1), with a ready-to-file brief.

**onsystem kept the same velocity — three releases in three days — and one of them answers the question the trial didn't.** [`onsystem`](https://github.com/dgesteves/onsystem) (73★, MIT, npm **0.10.0 → 0.10.3**: 0.10.1 on 10-27, 0.10.2 and 0.10.3 this morning) is the diff-scoped design-system guard whose NEVR-332 trial evidence completed 10-27 (#134 green on both contract layers, #135 seed failing both; promotion brief filed). What moved: **0.10.1 marks repo-authored text** — JSDoc, docs, component names, paths — in every MCP answer and CLI message as *description, not instructions* (quoted, line-breaks escaped so it can never start a line of its own): prompt-injection hardening in an agent-facing tool, exactly the property a skeptic would ask about before letting builder agents run the MCP server. **0.10.2** hot-reloads a config that was invalid at startup and answers a multi-repo `--root` per project instead of mixing their tokens. **0.10.3** layers a Tailwind v4 theme partial correctly (so `p-[13px]` suggests `p-3` again) and resolves workspace subpath exports the way Node does. Plus **0.10.0's** config layering — an app's `onsystem.config.json` now *extends* its design-system package's config rule-by-rule instead of replacing it — which is precisely the shape our post-freeze setup wants: `apps/stellarc-ui` extending a future Stellarc design-system package. One amendment for the pending promotion brief: **pin the Action at `@v0.10.3`, not `@v0`** — three releases in three days is exactly the float you don't want in a CI gate (proposal 2).

**The "design capability as an agent skill" pattern became a wave, and our own lane stayed parked on its decision.** Three new skill-form design systems since 10-09, none by an author we already tracked: [`Ludi-Herry/b-end-design-system-skill`](https://github.com/Ludi-Herry/b-end-design-system-skill) (B-end design system + component spec as an AI-executable Skill for Cursor/Claude/Windsurf; 37★ in three days, MIT) and its sibling `mobile-design-system-skill` (17★) on 10-25, and `hamza-hnt/Premium-Frontend-Skill` (16★, 10-09). They join `dithercn` (103★) and `Ludi-Herry/desktop-agent-ui` (65★) already on the radar: **five independent data points that design systems now ship with a SKILL.md channel so coding agents self-serve the system instead of violating it.** That reframes our own T02 end-state: the freeze's replacement is not just lint-in-CI + MCP-at-edit — a skill-in-context channel (our design contracts written *for the agent that is about to edit*) is the third leg, and it costs nothing to name in the post-freeze design-system merge brief (proposal 3). Meanwhile our lane is unchanged: all six freeze-gated PRs (#90/#91/#92/#108/#115/#118) sit at their 10-13→10-16 check runs (re-verified live this run: same 5-fail/6-pass profiles, every red attributed to T02 policy / typecheck-budget / absent-secret signing), and the #134/#135 evidence pair stands at its 10-26 checks. The lane is waiting on a decision, not on code — and the tooling it can be replaced with got better again this week.

Cost ≈ one markdown file maintained beside the lint config. Record it in the design-system merge brief when that lands; nothing to file today.
