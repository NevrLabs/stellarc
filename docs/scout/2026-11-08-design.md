## Proposals

### 1. ADOPT — Composer token contract (pre-registration into agent-view contracts)

File as one brief:

**Title:** agent-view contracts: pre-register the composer token contract (atomic tokens, metadata-preserving sends, IME-safe suggestions) before apps/web's composer exists

**Description:** The field just shipped the agent-composer pattern upstream: shadcn #12639 (11-08, implementing #12590) adds a token editor to the official prompt-input block — `/` and `@` trigger-character suggestion menus, keyboard+mouse selection, **atomic token deletion** (one Backspace deletes the whole token), **token metadata preserved in sent messages** (the renderer shows what was invoked/mentioned, not flattened text), Lexical as an **optional peer dependency** so plain-text textarea usage is unaffected, all three dialects (Base/Radix/Aria) in one PR. The requester's framing is ours to inherit: every project rebuilds this, and it is hard to get right. Stellarc's apps/web has no composer surface yet (grep-verified 11-08: no prompt/composer/token component under `apps/web/src`; no `components.json`, so the shadcn CLI isn't wired) — which is exactly when contract lines are cheapest. Proposal: pin a **composer token contract** section (or Maintenance addendum) into `docs/design/agent-view-contracts.md` on effect/v4 with five acceptance lines, all evidenced by #12639/#12590 plus our carried IME discipline: (a) a token is atomic — Backspace/delete removes it whole, never edits a character inside it; (b) a sent message preserves token metadata and renders the token as the token (skill/mention identity survives the send, consistent with our model-identity honesty lines); (c) `/`+`@` suggestion menus are keyboard- and mouse-selectable (arrows + Enter + click) and stay open through pointer-selection of an IME-composed query (#6176's stale-IME lesson is the adjacent failure); (d) IME composition is never broken at a token boundary — composition state outranks token parsing; (e) the composer degrades to plain text if the rich editor fails to load — Send never bricks (the Lexical-optional-peer design is the same shape). Docs-only, no dependencies, no app code. The block-vs-build decision (pull the registry prompt-input block via a wired CLI, or build the contract natively on Base UI) is explicitly deferred to the Builder run that opens the composer surface.
