### 3. WATCH (fold lines) — the day's law-shaped datapoints

- **(a) Disabled-for-assistive-technology sweep (gpui-kit #4195/#4193/#4178/#4188)** — a disabled accordion trigger, breadcrumb item, menu item, or button-group child is *marked* disabled for AT, not just styled. Acceptance-line material for apps/web: every disabled interactive primitive in the composer/dialog surface carries its disabled state semantically (aria-disabled), never only a opacity/pointer-events style.
- **(b) Dialog focus law (gpui-kit #4186/#4180/#4191)** — dialogs are named by their title with the topmost marked modal; focus moves to the first control on open; and closing returns focus **only when nothing else has taken it** (focus return is conditional on observed focus ownership, not unconditional). Pairs with the §H keyboard-focus honesty laws already pinned (NEVR-774).
- **(c) Unrendered-row estimation, third codebase (gpui-kit #4182 `with_uniform_item_height`)** — Multica #10648 (react-virtuoso first-measured heights) → #10874 (content-derived estimates) → now gpui-kit's uniform-height hint for unrendered rows. The law: a virtualized list needs an explicit, bounded height policy for rows it has never rendered; first-measurement extrapolation is the defect. Pre-register for apps/web's virtualized transcript/board surfaces.
- **(d) IME candidate-window placement (NSH #3411)** — clicks, keys, AND the IME candidate window land on the line where it is shown (multiline input). Joins the 11-26 IME/CJK family: composition state outranks token parsing, the caret never flashes mid-composition, platform marked text never lands as literal text — and now: the candidate window follows the composed line.
- **(e) Never pump messages inside a batch (NSH #3402)** — `openUrl`/notifications aborted with `RefCell already borrowed` because messages were pumped mid-batch; the fix is structural. Shell-lifecycle acceptance line for any reentrancy surface the desktop shell grows (our health-probe thread and window event batching are the adjacent seams).
- **(f) Webview X11 keyboard focus on click (gpui-kit #4183)** — on Linux, clicking the webview must take X11 keyboard focus; the Linux focus family (join the §H set when the desktop shell gets focus-management tests).
