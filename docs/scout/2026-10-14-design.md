## Proposals

### 1. ADOPT — resolve the freeze-guard conflict: give T02 an owner-sanctioned merge path for #90/#91/#92

The facts, verified today: T02 (added #58, 2026-09-19) hard-fails any PR touching `apps/stellarc-ui` — `desktop.yml` step "frozen UI tree untouched (T02)" and `tests/unit/desktop.test.ts:95` both enforce zero diff, with no allowlist. PRs #90 (deps), #91 (chat primitives), #92 (Radix tail + components.json) are all `MERGEABLE`, their pixel gates green, authors claiming frozen suites pass unmodified — yet all three are structurally red and cannot merge. PR #92's body explicitly asks for the owner decision. This proposal asks Talos to pick one of: **(a)** lift the freeze for these three PRs (approve-and-merge, accepting the pixel suite as the real gate), **(b)** add a narrow allowlist to T02 (e.g. `package.json`, `components.json`, `src/components/ui/*`, `src/lib/*` — files where "pixel-frozen" is not the risk), or **(c)** defer all three until the design-system merge. Option (b) is the surgical one: it keeps the guard for real UI-surface changes while letting dep/dialect/tooling PRs through. Either way, three ready ADOPTs from yesterday stop rotting. **This is a process ADOPT, zero new dependencies, zero code from this scout.**

### 2. TRIAL — pre-register the post-freeze design-system merge: named styles + `DESIGN.md` workflow

Two independent upstream signals now converge: shadcn's style system matured into 8 named styles × 3 dialects (with `base-nova` already chosen by #92), and the shadcn `DESIGN.md` skill (2026-10-09, flagged yesterday as TRIAL) maps a brand spec → tokens → variants → living design-system page. No dependency, no code yet — pre-registration only, so the merge starts from the paved path rather than inventing one.
