## Headline

Yesterday's port PRs (#77–81) all merged into an **`effect/v4` integration branch**, which still pins `effect 4.0.2`. Two upstream facts this run change how that branch should finish:

1. **Effect v4 core is batteries-included now.** Tarball-verified: `effect@4.0.4` exports `./ai`, `./cluster`, `./eventlog`, `./graphql` (new in 4.0.4, experimental), `./rpc`, `./sql`, `./workflow` from the core package. That means the standalone npm packages `@effect/ai` (0.37.0, peers `effect ^3.22.0`) and the `@effect/sql` umbrella (0.52.1, last release 2026-07-30) are **v3-only and will never see a 4.x** — the SQL layer was split into per-driver packages (`@effect/sql-pg`, `@effect/sql-sqlite-bun`, `@effect/sql-sqlite-node`, … all at 4.0.4) with `SqlClient`/`SqlError` living in core at `effect/sql/SqlClient`. The v4 tree already does the right thing (`@effect/sql-pg` 4.0.2, `import { SqlClient } from "effect/sql/SqlClient"` in `packages/drizzle-effect/src/index.ts:13`) — the risk is a stray v3-only `@effect/*` umbrella package sneaking back in via a future `bun update`. One-line hygiene check belongs in the v4 merge.
2. **`effect/ai` ships a full MCP server.** `McpServer` (streamable HTTP with session lifecycle: `DELETE` + `Mcp-Session-Id` termination, `MCP-Protocol-Version` negotiation, `allowedOrigins` enforcement, sessionless `v2026_07_28`, and a new `layerHttpRequestScoped` for request-scoped/serverless hosting added in 4.0.4), plus `McpSchema`, `Toolkit`, Anthropic/OpenAI structured output. Auth is deliberately left to the surrounding HTTP server. Stellarc's legacy MCP surface — `packages/kaneo-legacy/src/mcp/` (1,727 lines: `tools.ts` 915, `index.ts` 389, `oauth.ts` 152, `permissions.ts` 115, `oauth-store.ts` 83, `schemas.ts` 73) — runs on `@modelcontextprotocol/sdk`'s `McpServer` + `WebStandardStreamableHTTPServerTransport`. When the legacy tree migrates to v4, that port can drop the reference SDK entirely. Proposal 1 (TRIAL brief posted).

Also this run: **drizzle-orm upstream is still actively iterating Effect integration** — npm dist-tags `effect` (`1.0.0-beta.1-cdf226f`), `drizzle-effect` (`1.0.0-beta.13-f16bdca`), `effect3`, `effect-fixes`, `effect-validator`, `effect-cache-fix` all point at 1.0 betas/rcs (latest rc: `1.0.0-rc.5`, 2026-09-09). Our owned bridge stays the right call until 1.0 ships. And a **correction to yesterday's report**: "Jazz 1.2.0 stable" was a wrong-package read — npm `jazz` is an unrelated template engine (cliffano/jazz); Jazz-the-sync-framework is `jazz-tools`, latest **0.20.19** (2026-07-03) with a **2.0.0-alpha.59** line (2026-10-04), repo `gardencmp/jazz` (2,535★) last pushed 2026-09-07.

## Proposals

### 1. TRIAL — port the legacy MCP surface onto `effect/ai`'s McpServer during the v4 legacy migration
The reference-SDK MCP server in `packages/kaneo-legacy/src/mcp/` (1,727 lines) is one of the last big non-Effect islands in the backend, and Effect v4 core now ships a production-shaped MCP server that would delete the `@modelcontextprotocol/sdk` dependency from the v4 tree: streamable HTTP transport with session termination, protocol-version negotiation through `v2026_07_28`, origin allowlists, and Effect Schema-native tool definitions. Spike it as part of (not before) the legacy→v4 migration: port `tools.ts` first (largest file, pure schema+handler shapes), keep `oauth.ts`/`oauth-store.ts`/`permissions.ts` host-side (the module expects the surrounding HTTP server to own auth — which matches Stellarc's token gate design).
*(Issue brief posted as a separate comment for Talos.)*

### 2. ADOPT (no new brief) — one-line v4 dependency-hygiene check at merge time
`@effect/sql` (umbrella), `@effect/ai`, and `@effect/platform` on npm are v3-only and will never publish 4.x — their v4 content moved into core (`effect/sql`, `effect/ai`) and per-driver packages (`@effect/sql-pg` …). The `effect/v4` branch is already clean (only `@effect/platform-bun`, `@effect/sql-pg`, `@effect/opentelemetry`, all 4.0.2). Before `effect/v4` merges to dev, assert no v3-only `@effect/*` umbrella package appears in any workspace `package.json` — a later careless `bun update`/`bun add` could reintroduce one and drag the v3 `effect` peer into the tree. Fits inside NEVR-156's existing bump item; no separate issue needed.

### 3. WATCH — three upstream threads to re-check next libraries run
(a) **drizzle-orm 1.0** — upstream's `effect*` dist-tags show live integration work in the 1.0 betas; when 1.0 GA lands, decide whether `packages/drizzle-effect` absorbs upstream's integration or stays independent. (b) **hono 5.0.0-rc** — the rc line opened 10-10; calendar a major-bump pass with the Vite/vitest majors, not standalone. (c) **ACP v2.0.0-alpha** — no new alpha since 10-09; check the subagents RFD before building any new ACP surface. The `eventlog` module is byte-identical between 4.0.0 and 4.0.4 (16 modules) — the spike idea from yesterday is unchanged.
