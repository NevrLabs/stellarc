NEVR-14

Fix flaky sync test: entries double-apply on reconnect

Project Stellarc v2 Created Oct 3

sync.reconnect.test.ts fails ~1 in 8 CI runs: when the node reconnects mid-burst, the journal replay re-applies entries that the live path already committed. The lease holder flips between the two apply paths.

  • Reproduce by killing the node socket between append_entries 40–60.
  • Suspect the dedupe key drops the attempt id after a claim.
  • Fix + regression test with a deterministic reconnect schedule.
