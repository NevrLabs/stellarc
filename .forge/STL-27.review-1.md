1. **R03 fixture-freshness test missing entirely** (spec §7 R03). No test anywhere regenerates the dumps and compares logical equivalence (grep for make-legacy-fixture/make-destination-golden in tests/: none). Latent trap proven by reviewer: `canon.ts:530` seed inserts `public.event` relying on `DEFAULT now()` for created_at, so the committed golden is NOT reproducible — the diff shows `2026-09-11 22:56:37…` vs fresh `2026-09-12 00:56:05…`. Fix: commit an R03 integration test (regenerate into tmp → restore both → compare normalized plain-SQL dumps, red on a one-row mutation of the committed dump) AND pin the event timestamp in `tools/reconciliation/canon.ts:530-531` (explicit created_at literal).
2. **R21 live mode unimplemented** (spec §1 "two modes", §7 R21, §8.6). `run.ts` defines `Mode` but has no live path — nothing can ever emit `mode:"live"`; the harness can never produce the wave's only source of reconciliation PASS. The test at `tests/integration/reconciliation.test.ts:147` ("live mode with no merged importer reports blocked") fabricates a T0-only DB and re-proves R04 blocked semantics — it is not R21 and does not exercise a live runner. Fix: implement the live arm (run the merged identity importer from the restored snapshot when present; per-query blocked-with-reason when absent; report `mode:"live"`; #1–#3 + #13/#14 identity subchecks), or attach an orchestrator ruling deferring R21 — as shipped the mode is dead code.
3. **R20 green-with-event arm untested** (spec §7 R20: "with contract event green"). Only the 14b-red half is tested. Fix: add a rollback test that flips one apikey to re-issue state AND inserts exactly one `identity:apikey-reissued` event → query #14 verdict green; plus a both-arms event (preserved hash AND event) → red (`apikey:preser…nt` arm exists in the SQL and is currently never fired by any test or sabotage).
4. **Incomplete precondition lists crash instead of blocking** (spec §2 "absence ⇒ blocked, never green"; R04). `tests/fixtures/reconciliation/manifest.json:72` (query 5) omits `legacy.board` and `legacy.board_key_alias`, both referenced in 05-ticket.sql's `keyed` CTE; `manifest.json:160-170` (query 12) omits `public.asset` and `public.repo`, both JOINed in 12-isolation.sql. Fix: add the four missing precondition entries and add a regression test that drops each SQL-referenced table and asserts verdict `blocked` for the dependent query.
5. **All-column fidelity gaps** (spec §5: #1/#4/#10 "all-column fidelity", #3 "rate-limit state preserved"). Columns verified never compared in any canon file: Q1 `account.access_token_expires_at`; Q2 `invitation.expires_at`; Q3 `apikey.last_refill_at`, `last_request` (rate-limit state!); Q4 `board.created_at`; Q7 `milestone.completed_at`; Q10 `repo.last_synced_at`, `repo_issue.author_avatar_url/external_created_at/closed_at`, `repo_pull_request.labels/additions/deletions/changed_files/merged_at/closed_at/external_created_at/external_updated_at`. Fix: extend the value-mismatch arms to full column sets, or record an explicit written exemption (timestamp non-fidelity rationale, sibling-owner signoff) in each affected header + README supersession note.
6. **§2/ADR 0010 instrumentation contract missed** (spec §2 names `Effect.fn("ReconcileCanon.<method>")` / `Effect.fn("ReconcileRunner.<method>")`; "DB access through the standard @effect/sql client wrapper"; R22 requires "db.* spans"). `tools/reconciliation/run.ts:57-110` uses `Effect.gen().pipe(Effect.withSpan())` — no `Effect.fn` anywhere in tools/ — and takes the raw `postgres` `Sql` directly, so no `db.system/db.operation/db.sql.table` spans exist and R22 cannot assert them. Fix: convert harness service functions to `Effect.fn` wrappers and route DB access through the @effect/sql client wrapper (statement text excluded), then extend the R22 test to assert db.* span presence with its own negative control.
