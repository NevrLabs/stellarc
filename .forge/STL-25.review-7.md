## DEFECTS (numbered, file:line, exact fix expected)

1. **[BLOCKER — spec §3 error union; empirically re-verified this cycle]** `packages/sync/src/index.ts:196-206` (`sseEffect` pre-stream `Effect.tryPromise(() => self.ssePage(org, url)).pipe(Effect.mapError((error) => error as Error))`) + `apps/stellarc-api/src/http.ts:148-150` (`Effect.catchAll((error) => Effect.succeed(errorResponse(error)))`): a qualifying SSE request with an expired/unknown handle returns **500 `{"_tag":"InternalError"}`** — spec mandates "Conflict 409 must-refetch (expired handle: JSON body, never a stream)". My replay: `STATUS 500 CT application/json BODY {"_tag":"InternalError","message":"Internal server error"}`. The http.ts non-200 passthrough branch (http.ts:140-146) is dead code — `sseEffect` only ever returns a 200 stream Response or dies. The third doc-comment block (~index.ts:181-186) claims this contract works — it does not. No test covers the path. Fix: map `SsePageError{status:409}` to the sanitized 409 must-refetch JSON Response before opening the stream (throw the existing `ConflictError` and catch it in http.ts, or return the engine `page()` 409 body passthrough as the long-poll branch does), delete the lying comment, add the S-test (qualifying SSE + expired handle → 409 JSON, never `text/event-stream`).
2. **[BLOCKER — spec §2 fallback metric + S10; empirically re-verified this cycle]** `packages/sync/src/sse.ts:218-237` (first quiet page emits `up-to-date` unconditionally → `sawUpToDate` always true) + `sse.ts:263` (`fallback: !sawUpToDate`) + `packages/sync/src/index.ts:302` (disconnect summary hardcodes `fallback: true`): `stellarc_shape_sse_fallbacks_total` **never increments from real buffering** (server-side emission is not client-side traversal) and **always increments on ordinary client disconnects** — the exact inverse of "closed before first up-to-date flush".
