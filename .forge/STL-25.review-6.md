## DEFECTS (numbered, file:line, exact fix expected)

1. **[BLOCKER — spec §3 error union; empirically verified]** `packages/sync/src/index.ts:241-243` (`sseEffect` pre-stream `Effect.tryPromise(...).pipe(Effect.mapError((error) => error as Error))`) + `apps/stellarc-api/src/http.ts:148-150` (`Effect.catchAll((error) => Effect.succeed(errorResponse(error)))`): a qualifying SSE request with an expired/unknown handle returns **500 `{"_tag":"InternalError"}`** — spec §3 mandates "Conflict 409 must-refetch (expired handle: JSON body, never a stream)". Repro (my run): `fetch(.../shape?table=sync_probe&offset=<off>&handle=bogus&live=true&live_sse=true&experimental_live_sse=true`, `Accept: text/event-stream`) → `STATUS 500 CT application/json BODY {"_tag":"InternalError"}`. `ConflictError` (index.ts:621-624) exists for exactly this and is never thrown. Fix: in `sseEffect`, catch `SsePageError` with `status===409` and map to the 409 must-refetch JSON body (throw the existing `ConflictError`, or return the engine's own `page()` 409 Response passthrough — the long-poll branch at http.ts:155-180 already passes non-200 bodies through unchanged; mirror that), and add the missing S-test asserting 409+JSON on the qualifying-SSE-with-expired-handle path (currently no test covers it — my scratch test failed 500≠409).
2. **[BLOCKER — S10/metric semantics; empirically verified]** `packages/sync/src/sse.ts:263` (`fallback: !sawUpToDate`): under a buffering proxy the stream still emits its own `up-to-date` frames at each cycle close (sse.ts:218-237 emits them unconditionally after changes/first-page/at-deadline), so `sawUpToDate` is always true and **`stellarc_shape_sse_fallbacks_total` never increments from real buffering**. Instrumented run of S10-alone: all four buffered connections log `{"fallback":false,"close":"cycle"}` and the test FAILS (`TypeError: actual value must be undefined...` — metric has no datapoints); it only passes in a full-file run because S08's client-disconnect summaries carry a hardcoded `fallback: true` (index.ts:302) recorded into the same reader. Fix: the fallback signature must be "closed before the first up-to-date flush *reached the client*" — either (a) treat `close === "cycle"` at a cycle where zero bytes were ACKed past a buffering proxy as fallback (not implementable server-side alone — then say so in ADR 0012 and change the metric semantics + S10 to assert what is true), or (b) per spec §2 ("SSE connection closed before first `up-to-date` flush"), set `fallback` from "no up-to-date *frame was flushed before close*" — the current code emits up-to-date on the FIRST page unconditionally (sse.ts:227-240), which guarantees `fallback:false`; gate the first-page up-to-date emission (e.g. only when `hadChanges` on a caught-up quiet page is truly idle-flushed) or derive `fallback` from ka/comments never traversing. Additionally S10 must be order-independent: it passes only when S08 runs first; running `-t 'S10'` alone fails. Expected: S10 green in isolation, and an instrumented buffered run showing `fallback:true` summaries.
3. **[MAJOR — metric shape violates spec §2]** `packages/sync/src/sse.ts:52-54, 72-73`: `stellarc_shape_sse_frames_total` is a single counter incremented per frame; spec §2 requires "split by `control` vs `operation`". Fix: two counters (`..._frames_total{frame="control"}` / `{frame="operation"}`) or an attribute split; update S14/S15 assertions accordingly.
4. **[MAJOR — S12 harness cannot measure what its spec says]** `tools/measure-shape-concurrency.mts:46-56` (`pageSource`): each "shape" is a plain `fetch` of `...&shape-id=N` — (a) `shape-id` is not in the engine allowlist, so every request 400s; (b) offset=-1 plain fetches complete immediately (no held connection), so nothing holds a live HTTP/1.1 connection and no ceiling can bind; (c) the usage header claims a `--self-check` mode that boots a conn-cap-2 proxy — `grep self-check` shows only the comment; no such mode exists. Fix: drive real stock-client `ShapeStream`s (live=true+handle+offset) one per shape through the proxy fixture, add `shape-id`-free distinct shapes (or allowlist it), and implement the documented `--self-check` mode (reuse `startProxy` with a connection cap) so the S12 unit test exercises the actual browser path, or strike the claim from the header/ADR 0012.
5. **[MINOR — dead code / debris]** `packages/sync/src/index.ts:621-624` (`ConflictError`, unused once D1 is fixed it becomes used — until then remove or use), triple duplicated doc-comment on `sseEffect` (~186-199), `tests/integration/shape-proxy.test.ts:19-46` `_untilRow` never called. Fix: single doc-comment; delete `_untilRow` or use it; `ConflictError` wired per D1.
6. **[MINOR — ADR 0010 pattern]** `packages/sync/src/index.ts:206` `sseEffect(...)` is not `Effect.fn("Sync.sseEffect")` (class pattern: `shapeEffect = Effect.fn("Sync.shape")`). Fix: wrap it (the manual `makeSpan` stays as the child span) or record the deviation in ADR 0012.
7. **[MINOR — CI gate honesty]** `tests/gates.test.ts` 300 s kill vs integration suite ~470 s at PR head: pre-existing on dev (baseline exit 124 too), but this PR adds ~113 s of integration time (11 new tests, S08/S09 up to 15 s polls), pushing any chance of fitting under 300 s further away.
